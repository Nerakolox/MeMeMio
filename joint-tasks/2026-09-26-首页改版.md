# 首页改成入口页：搜索只做入口，主体是图墙 + 两条 rail

**状态**：`in_progress`（**web 段已完工并走查通过，见 §9**；api 段未开工——§3「api 端」那几条等 web 合入后开工）
**性质**：跨端，但**分两段、web 先**。web 端是主体（零接口改动），api 端只是收尾（删 `/search`）。**api 端等 web 端合入并验收之后再动手**，顺序反了会先把首页打断。
**涉及的 SPEC**：[§6.3.2](../spec/06-endpoints.md)（`random=true`，图墙继续用它）、[§6.3.3](../spec/06-endpoints.md)（`/search` 冻结入口 → 本任务后删除）、[§1.3](../spec/01-http.md)（「缺省 40」那条 `50` 的例外随之消失）、[§6.6.1](../spec/06-endpoints.md)（`tag-status`，状态条用它）、[§9.29](../spec/09-decisions.md)（本任务是它写明的「另开任务」）、[§9](../spec/09-decisions.md)（新决策条目）。

## 1. 为什么要做

[SPEC §9.29](../spec/09-decisions.md) 定下「检索并进 `GET /memes`」时写明了：**首页本轮不动，它的去向（产品负责人指向「像浏览器首页一样」）另开任务**。这份就是那个任务。

不改的理由已经用完了。合流之后，首页那条搜索结果成了一条**更差的重复列表**：同一句话，在 `/` 上不能筛、不能翻页，在 `/browse` 上能筛能翻。它存在只是因为 `/search` 还没死。首页要继续留着这个入口，就得回答「为什么同一件事有两个入口，其中一个残」——答不上来。

产品负责人 2026-09-26 的裁定是直接砍掉，不是缩短：

- **首页不搜索**。搜索框保留，但它**只做入口**——回车即导航到 `/browse?q=`，首页自己不渲染任何结果。
- **首页的第一屏给「翻」**。搜索交棒之后，首页剩下的唯一内容职责就是「不知道要找什么的时候随便看看」，而那一半今天没有替代物：浏览页有游标、有筛选、有排序，**没有随机**，「把三个月前那张图翻出来」只有 `random=true` 这一条路。
- **首页变成入口页**：搜索框 → 图墙 → 两条 rail（我的收藏、最近上传）→ 待处理状态条（按需出现）。

**这条改动可以零接口改动完成**——上表里每一个区块走的都是现有接口、现有参数。真正的收尾是把失去消费者的 `/search` 删掉，那是本任务第二段。

## 5. 两处裁定与它们为什么是明写偏离

### 5.1 图墙卡片只给「发送」

**裁定**：`MemeCard` 的 `actions` 槽放一枚直接发送按钮，**不挂 `MemeActions` 的 `⋯` 菜单**。全屏阅览器里那枚发送按钮**保留**。

**性质**：这是对 [检索筛选合一](../_archive/joint-tasks/2026-09-26-检索筛选合一.md) §3 裁定 4（「一个动作只出现一处」、发送统一走 `⋯` 菜单那一项）的**明写偏离**。裁定 4 的语境是**合并后的列表**，那里卡片同时需要编辑、删除、发送，所以菜单是对的；首页图墙**没有编辑也没有删除**（它是「随便看看」，不是管理面），为了一枚按钮挂一个只有一项的菜单是净负担，而发送是产品的核心动作、要一击可达。全屏阅览器那一枚同理保留（它是「点开之后想发」的出口）。

**实现要求**：

- 分流**复用** `lib/clipboard.ts`（`detectSendPath` / `SEND_LABELS` / `sendImage`）与 `lib/use-prefetch-share.ts`，**不在首页另写一份**——同一个动作两套行为是本端最不能犯的错（`clipboard-share.md §5`）
- 按钮走卡片右上角那个浮层位（`OVERLAY_BTN`，与 `⋯` 同位置同尺寸），**不是** 09-26 撤掉的那种图片下方全宽按钮
- 动图按 `isAnimated` 落到下载并说明原因，与其它两处逐字一致

### 5.2 键盘选图不做

**裁定**：`use-search.ts` 里的 ↑↓ 选图 / Enter 开阅览 / Esc 取消**整条不做**，随文件一起删。

**理由**：那条路径本来就是为首页的结果区写的（「搜完按 ↓ 挑图」），首页不渲染结果之后它没有落点。搬到浏览页是另一个量级的改动（要动浏览页的结果列、要在网格里做二维方向键、要走查那条「Tab 23 步才进第一张卡」一起修），产品负责人 2026-09-26 明确选了不做。

**要认下的代价**：键盘用户选图只能 Tab 进卡片，再按卡片自己的按钮（发送、收藏、图片帧）。首页因此**不能**有任何「只有键盘到得了」或「只有键盘到不了」的入口。走查那条「浏览页 Tab 23 步」仍是开着的缺陷，**不因本次裁定消失**，另条处理。

## 9. web 端验收

**结论**：web 段全部落地，实测走查通过，**无阻塞**。走查脚本 `web/scripts/verify-home-revamp.mjs`（一次性，不进版本库）**47 条断言全绿、0 红**，13 张截图在 `C:/Users/admin/AppData/Local/Temp/mememio-homerevamp/`。

### 怎么验的

- 环境：真 Chrome（`--headless=new`，零依赖 CDP，沿用 `verify-send-entry.mjs` 那一套）——前端 `127.0.0.1:5173`，替身 `127.0.0.1:3001`。
- 视口：**1264×900 桌面** 与 **390×844 手机**（`Emulation.setTouchEmulationEnabled`，页面里 `matchMedia('(pointer: coarse)')` 实测为真）各走一遍。
- 替身在 `web/scripts/mock-api.mjs` 补了三处缺口（该文件不进版本库）：`favorited=true` 与 `limit=8` 各回一批**互不相同**的图（此前两条 rail 与浏览页首屏回的是同一批，两条 rail 摆在一起长得一样，断言等于没验）；七个故障开关 `wallEmpty` / `wallFail` / `railsEmpty` / `railsFail` / `tagQuiet` / `tagRunning` / `tagStatusFail`。
- 「换一批」替身做不到（它对 `random=true` 永远回同一批），所以用 CDP `Fetch` 把请求拦下来自己回：第一轮原样透传替身的真数据，**点完之后那一轮回倒序 + 描述带标记**——「换了没有」是从 DOM 上读出来的，不是信它。

### 同日补做二：页面级的滚动条也换成同一根（2026-09-26，产品负责人当场提出）

「页面的也要换。**所有页面**」——上一条把 rail 与浏览页那两根统一了，可页面本身滚的还是
**窗口**：`AppLayout` 里包 `<Outlet>` 的 `div.flex-1.p-6` 一个 `overflow` 都没有，
于是首页 / 设置 / 导入 / 组件页显示的是系统原生条（桌面 15px，macOS 上随系统偏好整条消失），
与 rail、浏览页那几根 Radix 浮层条在同一屏上不像一套。

**改的是「谁在滚」**（`App.tsx`）：`SidebarInset` 加 `md:h-svh md:overflow-hidden`，
内容那一层换成 `<ScrollArea type="always">`（`md:min-h-0 md:flex-1`）。
手机档**刻意不动**（`md:` 前缀），三条理由写在 `App.tsx` 那段注释里：触屏不显示滚动条、
窗口能滚才有地址栏随滚动收起、`BrowseResults` 手机那一档读的就是 `window.scrollY`。

三处不是顺手的、是量出来才知道要做的：

1. **`type="always"` 是必需的**。Radix 的 viewport `overflow-y` 是「挂着条就 `scroll`、
   没条就 `hidden`」，而 `hover` / `scroll` 要等 `pointerenter` 才挂条——指针没进过内容区
   之前**这一页键盘 / PageDown / `scrollIntoView` 全都不动，且不报任何错**。
2. **Radix 那层 `display: table` 表壳必须压回块级**。表盒宽度上限是内容的 min-content，
   首页两条 rail 的行是 `shrink-0` 的横排，其 min-content 一路顶上来：实测 1264 窗口下
   **首页内容层被撑到 1200px**（其余页面都是 1008），`max-w-6xl` 那层因此按 1152 排、
   右半边被 viewport 裁掉。写法 `[&>[data-slot=scroll-area-viewport]>div]:block!`，
   **必须逐级直取**：写成后代选择器会连 rail 自己那层表壳一起压。压回后是 960，与改版前一致。
3. **`SettingsCard` 的 `scroll-mt` 要按档分**。那 56px 是「顶栏盖在内容上」时代的补偿，
   而 md 以上顶栏是滚动区的**兄弟节点**、不再遮挡——留着的话锚点每次都多推 56px
   （实测卡片顶 128px → 减掉后 72px，与改版前逐像素一致）。手机档仍是
   `--app-header-h + 1rem`，原值不动。
