# 评测集

**状态：`planning`** · 创建 2026-09-13

## 为什么

这是本项目投入产出比最高的一件事。没有它，下面这些问题只能靠拍脑袋：

- 打标提示词改了，是变好还是变坏？
- 用户想换一个模型，那个模型够不够格？
- 词表这么设计，不同模型真的能对齐吗？
- 0.6B / 4B / 8B 三档 embedding，差距值不值那点延迟？

在模型可配置 + 库共享之后，第 2 条尤其重要：**用户配的模型会影响所有人**，而「这个模型够不够格」需要一个客观答案。

完整论证见 [`docs/eval.md`](../docs/eval.md) 与 [SPEC §9.12](../spec/09-decisions.md)。

## 做完的标准

- [ ] 30 张图选定，覆盖面按 [`docs/eval.md`](../docs/eval.md) 的表
- [ ] 每张图标注 `expect`（三个维度 + ocrText）和 `queries`
- [ ] `manifest.json` 落在 `docs/fixtures/eval/`
- [ ] `api/scripts/eval.ts` 能跑通并输出五个指标
- [ ] 至少跑过 2 个不同视觉供应商，结果记在本文件末尾
- [ ] 词表合规率的结果反馈给[词表任务](2026-09-13-vocab-v1.md)

## 两端各自做什么

| 端 | 做什么 |
|---|---|
| 总管 | 选图、标注、维护 `manifest.json` |
| api | 写 `scripts/eval.ts`，输出指标 |
| web | **不参与**，这个任务不碰前端 |

严格说这不是跨端任务，放这里是因为**它阻塞的东西横跨两端**（词表转 `accepted` 之前，`web` 的筛选 UI 不该对具体词条做假设）。

## 注意

> ⚠️ **评测图片可能含擦边内容**（覆盖面里有这一类）。如果仓库会公开，图片本身必须放在仓库之外，`docs/fixtures/eval/` 只留清单和标注。

「同模板不同字」那两对图**最容易被忽略**。它们测的不是"能不能查出重复"，是"**会不会把不该判为重复的判成重复**"——那才是 [SPEC §9.7](../spec/09-decisions.md) 把判断权交给人的原因。
