# web 外壳顶栏吸顶

**状态**：`done`
**性质**：**web 单端**——不动 `api/`，不动 SPEC，不改任何接口与数据语义。

## 为什么要做

用户 2026-09-21 要求：「顶部承载侧边栏折叠的那部分改成 fixed 之类的」。

顶栏（`App.tsx` 的 `AppLayout`）**唯一的常驻内容就是折叠按钮**，而不吸顶时它只在页面顶部
可见。长页面往下一滚就再也折不动侧边栏了——这不是审美问题，是**唯一的折叠入口被滚走了**。

这件事与紧邻的[侧边导航](2026-09-21-web-sidebar-nav.md)那次是同一个来源：顶栏从「导航条」
降格成「只放折叠按钮」之后，它存在的理由就只剩那一个按钮；而按钮可以被滚走，意味着
这个降格只做了一半。

## 为什么是 `sticky` 不是 `fixed`

用户说的是「fixed 之类的」，取 `sticky`：

- `fixed` 把顶栏**抽离文档流**，于是「比它低」的偏移量之外还得再补一层 `padding-top`
  ——多一个会漂的量。
- `sticky` 的高度仍在流内，变的只是它在视口里的位置。唯一的代价就是下面这三处偏移量。

`SidebarInset` 是 `relative`、`SidebarProvider` 是 `flex min-h-svh w-full`，祖先链上
**没有 `overflow: hidden`**，所以 sticky 的滚动容器就是文档本身，吸顶成立（实测印证）。

## 三个「必须比它低」的落点

顶栏占住视口最上面 3.5rem 之后，页面里凡是要对齐视口顶边的东西都得往下让。散着写三个
`56px` 不会报错，只会让某天改高度时漏掉一两处，且都是**肉眼才发现得了的错位**：

| 落点 | 改法 | 不改的表现 |
|---|---|---|
| 顶栏自己 | `h-(--app-header-h)` | 高度与偏移量对不上 |
| `.browse__sidebar` 的 sticky `top` / `max-height` | `var(--app-header-h)` / `calc(100vh - var(--app-header-h))` | 筛选栏滑到顶栏底下（顶栏有实色底，压得住它）——上半截看不见但**不报错**；高度不减则底部伸到视口外 |
| `SettingsCard` 的 `scroll-mt` | `calc(var(--app-header-h)_+_1rem)` | `#invites` 这类锚点落进顶栏底下，`scrollIntoView()` 照样返回成功 |

公共值放在 `src/index.css` 的 `:root`（`--app-header-h: 3.5rem`），**不在 `@theme inline` 里**
——`inline` 不输出变量，`var(--app-header-h)` 会解析成空（同圆角刻度那份运行时副本的理由）。
三处都走 `var()`，没有一处写死。

两个实现细节，都是「写错了不报错」的那类：

- Tailwind 工具类里 `calc()` 的 `+` 两侧必须是空格，而空格要写成 `_`：
  `scroll-mt-[calc(var(--app-header-h)_+_1rem)]`。写成 `+1rem` 整条会被浏览器丢弃
  （CSS 规定 `calc()` 的 `+` / `-` 两侧必须有空白），`scroll-margin-top` 静默变回 0。
- 顶栏要 `bg-background`：省了不报错，是页面内容从顶栏底下透出来。`z-10` 与桌面侧边栏
  同层（DOM 在后，压得住它），且低于 Sheet / Dialog 的 `z-50`——手机端的导航抽屉要盖得住它。

## 实测（Playwright + 系统 Chrome，1280×720 / 390×844）

**登录态是 route 打桩的**（`/auth/me` 回一个 admin，`/memes` 回 40 条假数据把页面撑高，
其余 500）。**这验的是几何，不是接口联调。** 前两行是改动前后跑同一份脚本的对照：

| 量测 | 改前 | 改后 |
|---|---|---|
| `/browse` 滚到 600 时顶栏 `top` | **-600**（整条滚出视口） | **0** |
| `/browse` 滚到 1200 时顶栏 `top` | **-1200** | **0** |
| `/browse` 筛选栏 `.browse__sidebar` 的 `top` | 0（与视口顶齐平） | **56**，与顶栏下沿间隙 0 |
| `/browse` 筛选栏高度 | 720（= `100vh`，页尾时顶部会被切） | **664** = `100vh - 56px` |
| `#invites` 锚点落点 | 卡片 `top` 16，`scroll-margin-top` 16px | 卡片 `top` **72**，顶栏下沿 56 → **间隙仍是 16px**（原意保留） |
| 顶栏 `position` / 高度 / `z-index` | static / 56 / auto | sticky / 56 / 10 |
| 顶栏底色（浅 / 深） | — | `oklch(1 0 0)` / `oklch(0.145 0 0)`，**实色** |
| 顶栏左沿 vs 侧边栏右沿 | — | 256 / 256，**正好接上，不重叠** |
| 滚到页底后点折叠按钮 | （Playwright 每次点击会先自动滚回元素，量不出来） | `expanded → collapsed`，顶栏仍在 `top: 0` |
| 手机 390×844：顶栏 | 滚到 800 时 `top` **-800** | `top` **0**，触发器 44×44 |
| 手机：抽屉与顶栏的层叠 | — | 抽屉 `z-50` 盖住顶栏 `z-10`，顶栏区域取点命中的是抽屉 |
| 手机：抽屉里点导航 | — | 路由变 `/import`、抽屉收起（上一轮修的 registry 缺陷没被弄坏） |

顺带确认的两处：`--app-header-h` 在深浅两套下都解析成 `3.5rem`（深色块只覆盖颜色，
不需要再声明一次高度）；`dist/assets/index-*.css` 里四条声明都真实产出
（`height:var(--app-header-h)`、`top:var(--app-header-h)`、
`max-height:calc(100vh - var(--app-header-h))`、`scroll-margin-top:calc(var(--app-header-h) + 1rem)`）
——Tailwind v4 对解析不出的工具类**什么都不生成**，只看源码看不出来。

## 已知边界（记录不修）

- **页尾最后约 24px 的滚动里，筛选栏顶部会被顶栏盖住 24px。** 这是 `position: sticky`
  的容器夹紧：`.browse` 的底边比「筛选栏自然高度 + 顶栏高度」更早结束，而内容列底部
  还有一圈 `p-6`。**改动前同样存在，只是方向相反**——改前改后都在页底把筛选栏顶出去 24px
  （改前 `asideTop: -24` 即被切在视口上方，改后 `+32` 即压在顶栏下面）。量级相同，
  都不是新引入的；要根治得让内容列底边再长出一截，属于另一件事。
- 顶栏在手机端也吸顶。这是有意的：抽屉入口（就是那个折叠按钮）在手机上同样不能被滚走。
- 吸顶之后顶栏一直占着 3.5rem 的视口高度，手机端可用的内容高度少了这些。
  没有做成「向下滚时隐藏、向上滚时出现」——那是另一套行为，本次只把入口固定住。

## 不做

- 不做滚动方向感应的隐藏 / 显示（`intersection-observer` 那套）。
- 不给顶栏加标题、面包屑、搜索框（各页自己有标题，见[侧边导航](2026-09-21-web-sidebar-nav.md)的决策表）。
- 不把 `.browse__sidebar` 的 sticky 换成 `position: fixed`——它现在的高度与让位量都对，
  换 fixed 只会多出一处要手算的 `padding`。
