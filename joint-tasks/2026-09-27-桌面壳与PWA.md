# 桌面壳（Tauri）与手机 PWA：补「快速调出、直接发送」

**状态**：`planning`——**待讨论**，§4 的问题没裁定前不开工、不写实现代码
**性质**：跨端（新增桌面壳工作区 + web 能力分流 + api 一个探测接口）；PWA 部分可拆成 web 单端先做。
**来源**：2026-09-27 对话，「桌面端移动端是 PWA 好还是单独开发，要能快速调到表情包」。
对应 [docs/product.md §5](../docs/product.md) 第 3 条「浏览器扩展 / 桌面端」。

## 1. 为什么要做

「快速调到表情包」分两步：**唤出**和**发送**。[SPEC §9.2](../spec/09-decisions.md) 已写明 Web 形态的边界：

| | 唤出 | 发送 |
|---|---|---|
| 手机 · 浏览器 / PWA | 主屏图标、全屏打开，接近原生 | `navigator.share({files})`，动图也行——§9.2 认定的体验最好的一端 |
| 桌面 · 浏览器 / PWA | **没有全局快捷键**，要先切到浏览器 | 静图能复制；**动图写不进剪贴板**，退化为下载 |
| 桌面 · 原生壳 | 全局快捷键呼出小窗，发完隐藏 | 能把**文件**写进系统剪贴板，GIF 直接 Ctrl+V 进微信 |

桌面端缺的两样 PWA 补不了，只能靠原生壳。手机端为这点做原生 App 不划算：原生多出来的主要是输入法里直接出图，工作量要翻几倍。

**倾向**：手机端做 PWA；桌面端用 Tauri 薄壳。两者都复用现有 web，不另写一套前端。

## 2. 壳怎么连后端（倾向方案 A）

### 方案 A：壳直接加载部署好的站点（倾向）

- 首次启动填**服务地址**（如 `https://meme.example.com`）并存在本地；之后 WebView 直接打开这个 URL。
- **鉴权不变**：页面本身就在站点域名下，同域 httpOnly cookie（[SPEC §3.1](../spec/03-auth-permission.md)）照常能用，不用 CORS，不改成 token。
- **不需要 API 版本管理**：网页永远是服务器上的当前版本，与 [SPEC §8](../spec/08-collaboration.md)「前后端同时上线、不做版本并存」一致。服务器更新时壳不用跟着发版。
- 壳与网页之间只有**三个原生能力**：全局快捷键、GIF 以文件写进剪贴板、隐藏窗口。
  网页按「能力在不在」分流，旧壳缺某个能力时回落到现有行为。要管的是壳的能力集，不是 API 版本。
- 安全：Tauri 2 默认不给远程页面开原生能力，要用 capabilities 的 remote 配置放行。服务地址是用户填的，不能写死在配置里，所以要**运行时只对用户填的那个源授权**，并且只开这三个命令。

### 方案 B：前端打包进壳，远程调 API（不倾向）

- 页面源是 `tauri://localhost`，与 api 跨域：cookie 要改成 `SameSite=None` 或整套换 token，还要配 CORS，**动 SPEC §3 的鉴权契约**。
- 本地前端与服务器各自升级，**才真正需要 API 版本并存和兼容期**，与 SPEC §8.4 冲突。
- 唯一好处是离线能开界面，但搜索和发送都离不开服务器，这个好处没有意义。

## 3. 各端大致要改什么（未定稿，供讨论）

**桌面壳（新工作区，暂名 `desktop/`）**
- 首启填地址 → 调 api 探测接口校验 → 加载站点。
- 全局快捷键呼出 / 隐藏一个小窗（窗口尺寸和位置记忆待定）。
- GIF 以文件（Windows `CF_HDROP`）写进剪贴板。Tauri 官方 clipboard 插件**不支持写文件**，要用第三方插件或自己写 Rust。
- 托盘常驻、开机自启（可选）。

**web**
- 能力探测：在壳里时动图也走「复制」，否则维持 `lib/clipboard.ts` 现有分流。
  **必须复用同一套分流，不另写一份**（`clipboard-share.md §5`）。
- 小窗形态：呼出后焦点直接进搜索框，回车选图、发送后通知壳隐藏窗口。
- PWA：manifest、service worker（只缓存外壳，不缓存 `/api/*`）、图标；Android 可加 `shortcuts` 直达搜索。

**api**
- 一个公开的探测接口，例如 `GET /api/v1/meta` → `{ name: "mememio", version }`，用来确认填的地址确实是 MeMeMio 服务。新增接口按 SPEC §8 走。
- 若 PWA 要做 `share_target`（从别的 App 分享进库），需要一个接收上传的入口，属于另一条跨端契约。

## 4. 待讨论

1. **方案 A 还是 B**：倾向 A。
2. **PWA 是否先拆出来单独做**（web 单端，改动小，手机端马上受益）？
3. **`share_target` 要不要做**：把「存图」也补上，但它是新的跨端契约。
4. **桌面壳是否只做 Windows**：macOS 的文件剪贴板写法不同，工作量再加一份。
5. **过渡方案**：先让桌面浏览器装 PWA、固定在任务栏，用 Win+数字唤出。能补上唤出，发不了动图的问题还在。要不要先推荐这个？
6. **仓库放哪**：`desktop/` 作为第三个执行工作区（要补 `desktop/AGENTS.md`，并更新根 `AGENTS.md §1` 地图），还是单独开仓？

## 5. 开工前必须先验证

- **从剪贴板粘贴的 GIF 文件，进微信 / QQ 之后还是不是动图**。这是做桌面壳的全部理由，不成立就不做。
  可以连同 [SPEC §9.12](../spec/09-decisions.md)「拖进微信窗口是否可行」一起测。
- Tauri 2 remote capabilities 能否按运行时填的源授权；不能的话，方案 A 的安全边界要重新设计。
