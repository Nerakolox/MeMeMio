# 手机 PWA：装到主屏，独立窗口打开

**状态**：`planning`（2026-10-01 产品负责人指示「赶紧做掉」，从 [桌面壳（Tauri）与手机 PWA](2026-09-27-桌面壳与PWA.md) 拆出。**待开工，先回填一份实施计划再动手**）
**性质**：**web 单端**。预期 api 一行不动（见 §4.4 的实测条件）。不动 SPEC。

> **用词**：本文件的「**静态外壳**」（app shell）指数产物的 `index.html` + `assets/`，**不是** Tauri 的「壳」。项目里「壳」已经被[桌面壳任务](2026-09-27-桌面壳与PWA.md)占用了，本文件一律不简称，凡出现都写全「静态外壳」。
>
> **两件事的关系**：手机 PWA 与桌面 Tauri 是**两个东西**，只共享同一份 web 产物。拆开之后**有一处仍然互相影响**，两边都记了：桌面壳走的是「加载线上站点」，所以它会**跟着装上本次这个 service worker**（见 §8 第 6 条）。

## 1. 为什么要做

[SPEC §9.2](../spec/09-decisions.md) 把手机端的「唤出」和「发送」分开算：

| | 手机现状 |
|---|---|
| 唤出 | 只能从浏览器书签进；有地址栏、有标签栏，**在微信里点开还会被套一层浏览器** |
| 发送 | `navigator.share({files})` 已经做好了（`lib/clipboard.ts`，动图也能发）——**这一半不用做** |

所以本任务只补**唤出**那一半：装到主屏 → 图标打开 → 独立窗口、无地址栏、跟原生 App 一样切回来。这是 PWA 在手机上唯一的、也是够用的收益。

**不要顺手去改发送路径。** 已有的分流（触屏 → `share`、桌面 → 剪贴板 / 下载）是 [clipboard-share.md §5](../web/agents/rules/clipboard-share.md) 的核心，装成 PWA 之后 `touchPrimary()` 的判定不变，行为应当逐字一致——**这也是本任务的一条验收项**（§6 第 6 条）。

## 3. 做完的标准

1. 手机 Chrome / Edge 打开线上站点，**出现「安装」入口**，装上后主屏有图标，点开是**独立窗口**（没有地址栏），冷启动能直接进首页。
2. Android 上图标不被系统裁掉（`maskable` 那份四周留够安全边距）；iOS 用 Safari 的「添加到主屏幕」，图标不是白板（`apple-touch-icon`）。
3. 深色 / 浅色系统配色下，状态栏颜色与页面背景一致（`theme-color`），**不出现白顶**。
4. 断网后从主屏图标打开：**静态外壳能起来并给出可理解的界面**（不白屏、不转圈卡死）。断网时的接口失败走现有错误呈现，不新增一套。
5. 有过一次访问之后，`/assets/` 下的静态资源从缓存命中，**不重复走网络**。
6. **`/api/*` 与 `/auth/*` 一个字节都不进缓存**，SSE 不被拦截、不被缓冲；复制 / 分享的行为与装 PWA 前逐字一致。
7. 发一次新版：老用户拿到的静态外壳能更新（不是永远停在旧产物上），且不会有「旧 HTML 引用了已被删掉的资源」的白屏。
8. `cd web && npm run typecheck` 通过；文档链 0 失效。

## 4. web 端要改什么

### 4.1 新增文件

- **`web/public/sw.js`**——手写，无构建期预缓存清单（§5 是完整策略）。放 `public/` 是因为 Vite 把它原样复制到产物根目录，于是它的作用域正好是 `/`，正是需要的样子。
- **`web/public/manifest.webmanifest`**——`name` / `short_name` / `start_url: "/"` / `scope: "/"` / `id: "/"` / `display: "standalone"` / `lang: "zh-CN"` / `icons` / `theme_color` / `background_color`。
- **PNG 图标**（提交进库，见 §4.3）。
- **`web/src/lib/pwa.ts`**（新）——注册逻辑，只有一个 `registerServiceWorker()`。**把「注册」这件事集中在这一处**，别的文件不许再碰 `navigator.serviceWorker`。

### 4.2 改动现有文件

- `web/index.html`：加 `<link rel="manifest">`、`apple-touch-icon`、`theme-color`（深浅两条）、`mobile-web-app-capable` 与 `apple-mobile-web-app-*`。**`viewport` 要不要加 `viewport-fit=cover` 先别动**，见 §9 第 1 条。
- `web/src/main.tsx`：调一次 `registerServiceWorker()`。
- `web/agents/rules/styling.md`、`web/AGENTS.md`：如果里头有「只有 SVG、不引 PNG 图标」之类的表述，同步。

### 4.3 图标怎么来

仓库里只有 SVG（`public/mememio-mark.svg` 等），Android 的安装判定要 PNG。**仓库里已经有 `sharp`**（`api/node_modules/sharp`，0.35.4），写一个一次性脚本把 SVG 光栅化：

| 产物 | 尺寸 | 用途 |
|---|---|---|
| `icon-192.png` | 192 | `any` |
| `icon-512.png` | 512 | `any` |
| `icon-maskable-512.png` | 512 | `maskable`：mark 缩到约 80%，四周**填底色**（安全区内不被裁） |
| `apple-touch-icon.png` | 180 | iOS，**不能透明底** |

脚本放 `web/scripts/`，跟 `verify-*.mjs` 同例：**产物提交、脚本本身 gitignore**。理由写进脚本头：这是品牌资产的一次性转换，不是构建步骤。

### 4.4 预期不动 api（要实测）

`api/src/web-dist.ts` 的 `mountWebDist` 是按**整个产物目录**挂的（`serveStatic({root: dir})`），`web/public/` 的东西落到产物根目录也就落到 `/*` 上——所以 `/sw.js`、`/manifest.webmanifest` 会被它返回，**不需要改 api**。

但有两处**只能实测**，代码上看不出来：

1. `serveStatic` 的 mime 表认不认 `.webmanifest`。不认识的话它可能返回 `text/html`——表现是「安装入口不出现」而不是报错。
2. `sw.js` 的 `Cache-Control`。默认没有这个头，而浏览器对 SW 主脚本默认**不走** HTTP 缓存，所以大概率没事。

**实测不对再回总管开 api 小任务**，web 端不自己去改 `api/`（红线）。

## 5. 缓存策略（最容易做错的地方，照着写）

**只做运行时缓存，不做构建期预缓存清单。** 理由：产物文件名带内容哈希，天然不可变，第一次用就是可以永久缓存的——不需要在构建时列清单，也就不需要多一个依赖、不需要多一个构建步骤。

```
导航请求（mode: 'navigate'）
  网络优先 → 成功则更新缓存里的 index.html
          → 失败（离线）则回缓存里的 index.html
/api/*  /auth/*            → 直接放行，不缓存、不读缓存、不拦截（SSE 就靠这条）
/assets/*                  → 缓存优先（内容哈希，不可变）；未命中走网络
manifest / 图标 / SVG      → 缓存优先，带后台更新
其余同源 GET               → 网络优先，成功则缓存
非 GET、跨域               → 一律放行
```

四条硬要求：

1. **绝不缓存 `/api/*` 与 `/auth/*`。** 一旦缓存，拿到的是别人会话下的响应或者过期数据——这是安全边界，不是性能取舍。
2. **只缓存「该有的东西」。** 缓存静态资源前检查 `response.ok` 且 `Content-Type` 对得上；**尤其不能把 `text/html` 当成 JS 缓存**。SPA 回退对任何未命中路径都返回 `index.html` 且状态是 200，写漏这一条的表现是「某个资源坏了，而且一直坏」。
3. **版本号是一个手改的常量。** `SW_VERSION` 换一次，`activate` 时删掉其它所有 cache。运行时缓存没有版本，不这么做缓存会随每次发版一直涨。**已知放宽**：bump 之前旧资源不会被清（真机上表现为占用增长，不影响正确性）。
4. **只在生产注册**（`import.meta.env.PROD`）。开发态注册会把 Vite 的 HMR 挡在缓存后面，症状是「改了代码页面不动」——这种坑排查起来很贵，直接从源头掐掉。

## 6. 验收

**手段**：构建产物 + 一个零依赖静态服务器 + 现有替身 api，全部走 `127.0.0.1`（**它是安全上下文，SW 在它上面可用**，不需要 HTTPS），CDP 驱动系统 Chrome。**注意开发态不注册 SW，所以验收必须跑 `npm run build` 之后的 `dist`，不能再拿 vite dev server 当被测对象**——这需要给验收脚本补一个能同时出静态文件和 `/api` 替身的服务器；端口沿用可配置的惯例。

1. manifest 能取到、能解析、必需字段齐、图标 URL 都能 200。
2. SW 注册成功、`activated`、`navigator.serviceWorker.controller` 存在。
3. 二次访问：`/assets/*` 命中 cache（断言「不再发网络请求」）。
4. **遍历所有 cache，断言里面没有任何 `/api/` 或 `/auth/` 的条目**（这条要写死，它是 §5 第 1 条的机器化形式）。
5. `Network.emulateNetworkConditions` 断网后导航：静态外壳能起来；此时 `/api` 请求失败，界面走既有错误呈现，**不白屏**。
6. **装成 PWA 前后，复制 / 分享的分流判定不变**——`touchPrimary()` / `canShareFiles()` / `resolveAction()` 的输入输出逐条对照（`lib/clipboard.ts` 的现有用例或直接断言）。
7. `npm run typecheck` 通过。

**验不了的，要如实写**：headless 里点不出安装面板（`beforeinstallprompt` 要 HTTPS + 用户参与度），**「图标长什么样、独立窗口什么手感、iOS 加到主屏成不成」必须在真手机上过一遍**——至少一台 Android Chrome、一台 iOS Safari，记下机型和浏览器版本。没测就写没测。

## 8. 已知风险与欠账

1. **`display: standalone` 与安全区**：现在全仓**没有任何一处** `env(safe-area-inset-*)`，`viewport` 里也没有 `viewport-fit=cover`。这两件事要一起做，只加 `viewport-fit=cover` 会让内容顶到刘海和 Home 条下面。**本任务先不加 `viewport-fit=cover`**——先拿到「装到主屏」这个收益，安全区另开一条。如果实测发现不加就没法看，停下来问，别顺手改全局布局。
2. **缓存会涨**（§5 第 3 条的已知放宽）。
3. **`theme_color` 只能写字面值**：manifest 是 JSON，读不到 `src/index.css` 的 token，而 [styling.md](../web/agents/rules/styling.md) 要求颜色只引 token。这是那条规则的**唯一例外**，值的来源必须写在脚本或样式规则里说明清楚，不许来历不明地出现两组十六进制。
4. 本任务是手机上第一次真正「装起来」，**之前的全部验收都是浏览器标签页里跑的**——独立窗口下的安全区、键盘弹起、`navigator.share` 的面板形态都可能有新行为。
5. 深度链接没做：从主屏图标进来永远是 `start_url`，参数化入口（`?q=`、某张图）另说。
6. **与桌面壳的唯一交点**：[桌面壳](2026-09-27-桌面壳与PWA.md)走的是「加载线上站点」，WebView 里那个页面**就是本次这个站点**，所以它会跟着注册同一个 service worker、拿到同一套缓存——**本次落地等于顺手改掉了桌面壳的运行时行为**（将来壳里「离线显示的是缓存里的旧产物」这类现象，根子在这里，不在壳）。本任务**不为它做任何让步**，但要在[桌面壳任务](2026-09-27-桌面壳与PWA.md)里留一行，别让那边开工时才发现。
7. 桌面浏览器也会跟着出现安装入口——因为 manifest 是站点级的，不分手机。这不是本次的目标，但它是[桌面壳任务](2026-09-27-桌面壳与PWA.md) §4.5 那个「过渡方案」的免费实现，那边的裁定要知情。
