# 跨端任务

需要 `api` 和 `web` 同时动的事情放这里。判断标准不是工作量，是**「一端先合入会不会让另一端坏掉」**。什么时候必须开、什么时候不必，见 [SPEC §8.2](../spec/08-collaboration.md)。

命名 `YYYY-MM-DD-主题.md`。完成后移到 [`_archive/joint-tasks/`](../_archive/joint-tasks/README.md)，**不要删除**——它记录了这个决定是怎么来的。

## 状态

只有三个主状态，阻塞单列：

| 状态 | 含义 |
|---|---|
| `planning` | 契约还在讨论，**不写实现代码** |
| `in_progress` | 契约已转 `accepted`，两端在实现 |
| `done` | 联合验收通过，准备归档 |

各端只回填**本端**的任务和**有依据的**验证结果。没跑的测试不要写成跑过了。

## 当前任务

按优先级排列。**前三项都是「写核心代码之前必须先做」**，它们的结果会改变实现方式。

| 任务 | 状态 | 阻塞谁 |
|---|---|---|
| [评测集](2026-09-13-eval-set.md) | `planning` | 词表转 `accepted`、模型推荐值、所有打标相关的改动 |
| [词表 v1](2026-09-13-vocab-v1.md) | `planning` | `api` 的校验逻辑、`web` 的筛选 UI |
| [供应商探测](2026-09-13-provider-spikes.md) | `planning` | 降级判定逻辑、测试连接实现 |
| [梗名别名层](2026-09-13-meme-lexicon.md) | `planning` | 检索实现定稿、打标提示词 |
| [骨架搭建](2026-09-13-skeleton.md) | `done`（待联合验收） | 所有实现工作 |

前三项可以并行，第五项不依赖它们——**骨架可以先搭，只是不要在 `proposed` 的具体词条上做硬编码分支**。

[梗名别名层](2026-09-13-meme-lexicon.md)也不阻塞骨架，但它会改 `memes` 的读路径，**要在检索实现定稿前做完**。它和词表任务边界相邻却不是一回事：词表是闭集，梗名是开集，见 [SPEC §9.18](../spec/09-decisions.md)。

## 写任务的要求

每个任务文件至少要有：**为什么要做**、**做完的标准是什么**、**两端各自要改什么**。

不要写成一个待办清单。三个月后回来看时，「当时为什么决定这么做」比「做了哪几步」重要得多。

决策结论写完后要搬进 [SPEC §9](../spec/09-decisions.md)——**任务是过程，SPEC 是结论**。
