# 状态与导航

## 1. 能放 URL 的放 URL

搜索词、筛选条件、当前页签**全部放 query string**，不放组件 state。

```
/?q=今天真的不想上班
/browse?emotions=无语&tags=猫&isAnimated=true&favorited=true
```

理由不是「优雅」，是这个产品的具体场景：**用户会把一次搜索的链接发给别人**（「你搜这个，第三张」）。放在 state 里就分享不了，刷新也丢。

参数名与[接口参数](../../../spec/06-endpoints.md)保持一致，不做第二套映射。

## 2. 服务端数据不复制到本地 state

结果列表、Meme 详情、配置——**这些的真相在服务端**，本地只缓存，不做第二份可编辑副本。

编辑标签后重新拉取或就地更新缓存，**不维护一个「本地已改但没提交」的影子对象**。那会在并发编辑时产生「我改的怎么没了」，而这个库是共享的，[所有人都能编辑](../../../spec/03-auth-permission.md)，并发编辑是常态不是边缘情况。

用 TanStack Query 一类的数据层，或者自己写一个薄缓存。**不要引入 Redux**——这个应用没有需要全局协调的复杂状态。

## 3. 真正的本地 state 只有三类

| 类 | 例 |
|---|---|
| 纯 UI | 弹窗开关、hover、输入框未提交的值 |
| 会话级 | 当前用户（从 `/auth/me` 来，登出清空） |
| 进行中的导入 | 批次 id + SSE 推来的进度 |

第三类是唯一真正复杂的本地状态，见 [import-ux.md](import-ux.md)。

## 4. 路由

| 路由 | 说明 |
|---|---|
| `/` | 搜索，主入口 |
| `/browse` | 筛选浏览 |
| `/import` | 导入 |
| `/settings` | 用户设置 |
| `/admin` | 管理页，**仅 admin** |
| `/login` | 登录 / 注册 |

`/admin` 前端做路由守卫，**但那只是体验**——真正的权限在服务端。不要因为前端藏了入口就认为安全。

## 5. 登录回跳

`UNAUTHENTICATED` 跳登录页时**保留当前路由**，登录后跳回去。

用户从别人分享的搜索链接进来、发现没登录、登录完被丢到首页——搜索词就没了。这是最容易漏、也最容易被用户抱怨的一个细节。

## 6. 筛选与搜索是两条路径

**不要把它们合成一个「万能搜索框」。**

| | 走哪个接口 | 特点 |
|---|---|---|
| 搜索 | `GET /search` | 三路融合，**不分页**，最多 100 条 |
| 浏览 | `GET /memes` | 条件筛选，**游标分页**，无限滚动 |

两者的分页行为完全不同，混在一起会出现「搜索结果为什么滚不动了」这种解释不清的问题。

## 7. `uploader` 和 `favorited` 是筛选项，不是安全边界

「只看我上传的」「只看我收藏的」是**可选筛选**，不传就是全库。这是[设计本身](../../../spec/00-overview.md)。

**不要默认帮用户加上 `uploader=me`。** 那会让共享库看起来像隔离库，用户会以为别人的图搜不到。

## 8. 乐观更新

收藏 / 取消收藏可以乐观更新——失败回滚，代价小。

**编辑标签和删除不要乐观更新。** 编辑要等服务端的词表校验结果；删除是破坏性操作，让用户看到它真的成功了。
