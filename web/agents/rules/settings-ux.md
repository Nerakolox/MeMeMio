# 设置页与管理页

> **文案是契约，不是文案建议。** 见 [SPEC §9.9](../../../spec/09-decisions.md)。

## 1. 为什么这一页这么重要

用户会填各种中转服务。**填了不能用的模型却不知道为什么，是最糟糕的体验。**

约束必须写在输入框旁边，不能藏在文档里。这一页做不好，整个"模型可配置"的设计就落不了地。

## 2. 一个页面，两类分段

2026-09-18 起三个管理页并进了 `/settings`（见 `joint-tasks/2026-09-18-settings-merge.md`）。

| 分段 | 谁看得到 | 配什么 |
|---|---|---|
| 视觉模型 | 所有人 | 视觉主 / 副通道，**每人一份** |
| 邀请码 | 仅 admin | 生成与查看邀请码 |
| Embedding | 仅 admin | Embedding，**全站一份** |
| 用户 | 仅 admin | 角色与存储配额 |

**Embedding 仍然不属于普通用户的设置。** 管理员分段对普通用户**不渲染**，不是 CSS 隐藏，
也不是「藏起来的高级选项」——它全站一份，见 [SPEC §9.6](../../../spec/09-decisions.md)。
合并的是呈现，权限归属一个字没改。

> SPEC §9.6 / §9.9 的正文仍写着「两个页面」，那是按旧结构写的措辞，实质约束与本规则一致。
> 措辞归总管，偏差记在上面那份任务文件里。

旧地址 `/admin/*` 一律重定向到 `/settings` 的对应锚点，**不做成 404**。

## 3. 视觉模型收进「高级选项」

默认折叠。不填就用部署方的默认配置，那是经过验证的。

**这个折叠是有意的**：让改配置需要多一个动作，因为[改错了会污染所有人的搜索结果](../../../spec/09-decisions.md)。

必须显示当前用的是**部署方默认**还是**自己的配置**（接口返回 `source` 字段）。

折叠本身是 `Button aria-expanded` + 条件渲染（`VisionSettings.tsx`），**不是** shadcn 的
`Accordion`——里面装的是测试结果，而那个结果恰好是在折叠**已经展开之后**才出现的，
撞上 Radix 的高度快照缺陷会被静默裁掉，见 [styling.md](styling.md)。

## 4. 必须有的文案

这两段是契约，**不能删、不能弱化**：

**用户设置页 · 视觉模型**

```
接口要求
  · 需兼容 OpenAI /v1/chat/completions
  · 必须支持图片输入（多模态）。纯文本模型会报 unsupported content type
  · 必须能稳定输出 JSON。优先选支持 response_format: {"type":"json_object"}
    或 tool calling 的模型
  · 不需要关心 GIF / WebP 支持 —— 系统会统一转成 PNG 再发送

⚠️ 你的打标结果会进入公共库，所有人都会搜到
  · 不填就用部署方的默认配置，那是经过验证的，多数情况下不需要改
  · 换成质量更差的模型，影响的是所有人的搜索结果

推荐
  · DeepSeek V4.1 Flash —— 中文语感好，单张约 $0.0007
  · 副通道建议配一个内容策略更宽松的供应商，用于主通道拒绝时降级
```

**管理页 · Embedding**

```
⚠️ 这是全站唯一一份 Embedding 配置，对所有用户生效

接口要求
  · 需兼容 OpenAI /v1/embeddings
  · 输出维度必须 ≥ 1024，系统会统一截断并重新归一化到 1024 维
  · 强烈建议选择支持 MRL（套娃表征）的模型，否则截断会明显降低检索质量
  · ⚠️ 更换模型会触发全站重新索引，期间搜索降级为 OCR + 标签

推荐
  · Qwen/Qwen3-Embedding-4B（硅基流动）—— 支持 MRL，中文强，延迟适中
```

「你的打标结果会进入公共库」这一句**尤其不能删**——它是共享库代价在界面上的唯一体现。

## 5. 「测试连接」是这一页最重要的控件

每组配置一个独立的测试按钮。结果实时展示，**逐项列出探测到了什么**：

```
✓ 能接收图片
✓ 支持 JSON 模式
✗ 不支持多图输入 —— 动图将使用拼图模式
✓ 返回的标签都在词表内
```

不是一个「成功 / 失败」的红绿灯。用户需要知道**哪一项不行**，才能判断要不要换。

### 失败时原样展示 `rawResponse`

> ⚠️ **不要吞掉它，不要包装成友好文案，不要截断成前 100 字。**

用户面对一个中转服务，**只有看到原始返回才能判断是模型能力问题还是配置填错**。这是这个接口的核心价值，见 [SPEC §6.5.1](../../../spec/06-endpoints.md)。

用等宽字体、可折叠、可复制。**折叠不能变成截断**：`<pre>` 限高只是给它一个滚动区
（几百行返回会把整页顶走），**全文始终在 DOM 里**，复制拿到的也是全文。
这里可以用 `Accordion`——它装的是**已经拿到的字符串**，渲染完不再变；换成会长的内容就不行了
（见 [styling.md](styling.md) 那条高度快照）。

自动展开的时机：测试**不通过**时展开，通过时收起。注意 `Accordion` 的 `defaultValue`
只在挂载时生效，而两次测试之间组件是复用的——「先失败 → 改配置 → 再测通过」会留着上一次
展开的原始返回，所以 `TestResultPanel.tsx` 用它 `key` 跟着 `ok` 变来重挂载。

### 测试连接返回 200

不通过也是 200，结果在响应体里。**不要当 HTTP 错误处理**——那会丢掉 `rawResponse`。见 [http.md](http.md)。

## 6. 不测就不让保存

保存按钮在测试通过前禁用。服务端也会拒（`CONFIG_TEST_REQUIRED`），但**前端就该禁用**，不要让用户点了才知道。

改了任何一个字段（baseUrl / model / key）都要**重置测试状态**，之前的测试结果对新配置不作数。

## 7. API Key

- 显示为 `**** + 后四位`
- **回传这个字符串视为「不修改」**——用户不改 key 时直接提交表单即可
- 输入框是 password 类型
- 不要"为了方便"加一个显示明文的眼睛图标

见 [SPEC §3.5](../../../spec/03-auth-permission.md)。

## 8. 重建索引

换 embedding 模型且库里已有数据时，保存需要额外确认一次（`confirmReindex: true`）。

确认框要说清楚：**会触发全站重算，期间搜索降级为 OCR + 标签，但不中断服务。**
它是 `AlertDialog`（真模态：焦点锁在里面、Esc 关得掉），**不是**行内展开的一段说明——
这一步代价是全站的，值得多一次明确动作。两个按钮都要 ≥44px。

重建进度可查，和 Embedding 表单**并列**放在同一个分段里。**不要做成模态阻塞**——
它要跑几分钟，管理员应该能去干别的。

## 9. 统计

| 统计 | 范围 |
|---|---|
| 视觉模型分段（所有人） | **自己上传的**那部分：已完成 / 待处理 / 需人工 |
| 管理员分段 | 全站：已完成 / 待处理 / 需人工 / 索引过期 |

普通用户看到的统计只看自己的——那是他能负责的部分，也是他配的模型的成绩单。

**数据来自 `GET /memes/tag-status`（[SPEC §6.6](../../../spec/06-endpoints.md)），不另做接口。** 同一个接口
在 `/import` 的打标页签里也用来显示进度——两处问的不是同一个问题（这里问「我配的模型成绩如何」，
那里问「我刚传的图打好了没」），所以**界面各做各的，接口共用**。

管理员那一行的界面**还没做**（`scope=all` 的接口已经有了）。本规则里这一行的现状与排期见
[打标状态界面任务](../../../joint-tasks/2026-09-19-tagging-status.md) 的「明确不做」。

⚠️ 2026-09-22 起，全站的**已完成 / 待处理 / 需人工**三个数在「重新打标」那张卡里露了出来
（§10），但那是**重打标的进度**，不是这一行「统计」。这一行的完整形态还多一格**索引过期**，
它没有接口（`GET /admin/reindex/status` 的 `stale` 是另一个口径），仍然没做。

## 10. 重新打标

设置页管理员区块里、紧挨「重建索引」的那张卡（SPEC §6.4.3）。它和重建索引**形状像、实质相反**，
三处差别都在钱上，界面上必须体现出来：

| | 重建索引（§8） | 重新打标 |
|---|---|---|
| 幂等 | 是 | **否**——再点一次就是再花一遍全库 |
| 花谁的 | 部署方的 embedding | **图片上传者的**视觉预算 |
| 界面 | 点了就跑 | **确认框**，跑着时禁用 |

**「重复触发是安全的：服务端幂等」那句话不能抄过来。** 它成立的前提是幂等。这一张卡下面
写的是「花的是图片上传者的配置和额度；人工编辑过的图不会被覆盖」。

**确认框里必须说三件事**（SPEC §6.4.3 定死，不在前端现编）：花的是上传者的预算；
**重打可能让一部分图变成「需人工」而旧标签不会丢**（那是一个可用的回退值，不是数据损坏）；
人工编辑过的图会被跳过，**也因此不会获得新增的那一维**。默认焦点落在「取消」。

**「队列在跑就禁用」的判据只能是 `running`，不能是 `pending`。** `pending` 会由别人的上传造成，
更会由「上传者没配视觉通道」的图永远停在那个状态（是 §6.4.3 记着的已知缺口），拿它当闸门
等于把按钮**永久禁用**——不报错、也没有出路，比误点更坏。代价是两个 worker 恰好都在两次
认领之间时按钮会闪一下，兜底的始终是确认框。

**进度条的分母只能是「本次触发排上的条数」**（触发时记下的 `enqueuedCount`），服务端给不出分母
（进度复用 `GET /memes/tag-status`，不另做端点，SPEC §6.4.3）。所以离开这一屏再回来就只剩计数、
没有百分比——**那是正常的，不是残缺**。`enqueuedCount` 为 0 时不要设基线：没有分母就没有进度条，
硬设一个会除出 NaN。

**「0 条」有三种成因，界面必须分开说**（否则管理员只看到「0」，会以为按钮坏了然后反复点）：
本来就都在队列里、选中的图全被跳过、一张都没选中。被跳过的那两个计数里，
**`skippedUnconfiguredCount` 尤其不能吞**——那不是「干完了」，是「这些图重打不了，
因为它们的上传者没配视觉通道」，服务端专门留了这个计数就是为了让它说出来。
