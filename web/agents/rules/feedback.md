# 操作反馈

**每一个动作按钮按下去，用户都要知道发生了什么。** 这一份说的是「什么该说、在哪说」，
样式与层级在 [styling.md](styling.md) 的「全站提示（toast）」。

2026-09-24 立的规矩。起因是一次逐条实测：全站有一批按钮点下去**什么都不发生**
（登出没有 try/catch，网络一挂就是一条未处理的拒绝；无权限的删除 `preventDefault()` 后
直接 return；收藏失败静默回滚），另有一批**发生了但用户看不见**（编辑面板保存成功那句
「已保存」写在页面级 state 里，而它渲染的位置正好被模态侧边栏盖住）。

## 1. 四条判据

| # | 判据 | 例子 |
|---|---|---|
| 1 | **成功态已经看得见的，不弹成功提示** | 收藏的心形、导入的整页切换、筛选后的重取、重试出现的骨架屏、换一批 |
| 2 | **失败一律弹，且不自动消失** | 删除失败、登出失败、收藏失败、发送失败 |
| 3 | **成功态看不见的，弹** | 剪贴板写入、删除、生成邀请码、放弃修改 |
| 4 | **导航类不弹** | 侧边栏导航项、登录 / 注册提交、`/admin` 重定向、「去导入几张」 |

判据 1 和 3 是同一条的两面：**先问「用户此刻看得见什么」，再决定要不要说话。**
给看得见的结果补一句「操作成功」只是噪音；而剪贴板是**不可见**的，它必须说话。

判据 4：换页本身就是反馈，再弹一句等于把同一件事说两遍。

**系统分享面板也属于判据 4 那一类**——它自己就是反馈。`lib/clipboard.ts` 的 `sendNote`
在走 `navigator.share` 时返回 `null`，调用方据此不弹（既有设计，2026-09-24 保留）。

## 2. 失败不自动消失

常驻 + 关闭按钮，不是 4 秒。理由只有一条但足够：[http.md](http.md) §3 要求 `requestId`
能被用户抄下来去对服务端日志，而一个自己走掉的提示会在他抄之前消失。

**降级不是失败。** 取不到原图、改走「在新标签页打开原图」那条，用的是**中性样式**
（[http.md](http.md) §5），不是红色；但它需要用户自己动一下手，所以同样常驻，并带一个
真的 `<a target="_blank">`。

## 3. 保存走行内，不走 toast

「保存」属于**表单**，确认就近留在那张表单里。两处：

| 在哪 | 什么形态 |
|---|---|
| `MemeEditPanel` 保存 | 面板内行内「已保存」 |
| `UsersSettings` 每行保存 | 行内「已保存」，与同页另外三张卡一致 |

设置页**整体**保持行内（[http.md](http.md) §5 的「设置页不弹 toast」）：测试连接的逐项结果、
`rawResponse`、重建 / 重打标进度、Embedding / 视觉 / 运行参数的「已保存」全部照旧。
用户 2026-09-24 裁定的口径。**失败侧也跟着留在行内**——那里本来就是带 `requestId` 的
行内 `role="alert"`，成功改成 toast 会让同一行有两个渠道。

设置页里唯一的例外是**生成邀请码**：新行插在表格最上面，而管理员此刻正看着表单，
行内提示没有落点（判据 3）。

### 为什么不弹 toast（三条，任一成立就够）

- 抽屉是从右侧推出来的，右上角的 toast 会和它叠在一起；
- **Radix 模态给 `#root` 挂 `aria-hidden`**，模态开着时 toast **对读屏是隐藏的**——
  而「保存完不知道成没成」正是这次要修的那类问题，用 toast 修等于没修；
- 同一行的失败侧已经是行内 `role="alert"`，两个渠道说一件事。

## 4. 文案与时长只有一份

`lib/toast.tsx` 是**唯一落点**：`notifySuccess`（4s）/ `notifyFailure`（常驻 + requestId）/
`notifySend`（发送结果，降级那条带链接）。

**不在业务组件里直接 `import { toast } from 'sonner'`。** 理由与 `lib/clipboard.ts` 把发送
文案集中起来是同一条：同一个动作在首页和浏览页必须说同一句话，只改一处会让两页漂开。

文案本身各有归属——发送那几句仍由 `lib/clipboard.ts` 的 `sendNote` 定，`lib/toast.tsx`
只负责呈现。

## 5. 乐观更新的回滚必须说话

收藏走乐观更新，失败回滚。**回滚之后图标自己翻回去，与「这一下没点中」长得一模一样**：
用户会再点一次，而第二次同样失败。所以回滚是「界面先说了谎，事后再补救」，
补救本身得被听见——`notifyFailure('收藏失败，请重试')`。

成功**不弹**（判据 1）：心形填上了就是反馈。
见 [state-navigation.md](state-navigation.md) §8。
