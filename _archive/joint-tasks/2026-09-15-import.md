# 导入：上传、处理管线与待确认队列

**状态：`done`** · 创建 2026-09-15 · 验收关闭 2026-09-16

## 为什么

搜索和浏览已经完成，但库里没有任何图——注册要有效邀请码，注册了也没有导入入口。这是唯一能把图送进库的路径，做了它，三件事同时解锁：

1. **库里有真实数据**，搜索任务的「真数据渲染」和评测集的「真实图片 + 真实 embedding」两个缺口才能补上。
2. **存储配额从纸面变成真实约束**，配额显示、超限报错才有东西可验。
3. **待确认队列（近似重复图）**才有机会被真实触发，而不只是靠 mock 测。

导入涉及 R2 预签名上传、服务端图像处理管线（magic bytes → 去重 → pHash → 打标队列）、SSE 实时进度，以及待确认队列的对比与决策——这些都跨端，因此开跨端任务。

## 做完的标准

- [x] `POST /api/v1/imports`：签发预签名直传 URL，检查配额，返回 `batchId` 和每个文件的 `uploadUrl` + `tempKey`
- [x] `POST /api/v1/imports/{batchId}/commit`：触发服务端处理，202，不同步等待
- [x] 服务端处理顺序符合 SPEC §6.2.2 契约：magic bytes → SHA-256 精确去重 → pHash 近似去重 → 写 memes（`tag_status=pending`）→ 进打标队列
- [x] `GET /api/v1/imports/{batchId}/events`：SSE 进度流，发送 `progress` / `item` / `done` / `error` 四种事件；连接断开不影响服务端处理
- [x] `GET /api/v1/imports/{batchId}`：批次快照，SSE 重连失败时用，保留 24 小时
- [x] 精确重复（SHA-256）：静默跳过，`item.result = "exact_dup"`，删除暂存对象
- [x] 近似重复（pHash Hamming）：进待确认队列，`item.result = "needs_review"`，**不打标**
- [x] `GET /api/v1/imports/reviews`：当前用户全部待确认条目（跨批次），含双方并排信息
- [x] `POST /api/v1/imports/reviews/{batchId}/{fileName}`：`{ action: "import" | "skip" }`，处理后移出队列
- [x] `is_animated` 用帧数判定，不从 `mime` 推断（WebP/APNG 都可能是动图也可能是静图）
- [x] 超出存储配额时拒绝 presign（`QUOTA_EXCEEDED`），commit 时再检查一次
- [x] Web `/import` 页面：文件选择 → 直传 R2 → SSE 实时进度 → 完成摘要
- [x] Web 待确认页：双图并排对比，显示相似度，「仍然导入」/「跳过」两个操作
- [x] 错误展示完整（`UNSUPPORTED_FORMAT`、`FILE_TOO_LARGE`、`QUOTA_EXCEEDED` 分别展示不同文案）——实现完整；浏览器里实测过前两个，`QUOTA_EXCEEDED` 与 `INTERNAL` 只走了代码路径，转出为遗留项
- [x] `/import` 加进导航，套 `RequireAuth`

## 两端各自做什么

### api 端

**涉及的 SPEC：** §6.2（导入全节：presign、处理顺序、待确认队列）、§1.4（SSE 事件格式）、§1.5（幂等：SHA-256 去重）、§5.2（memes 表：去重字段、is_animated、tag_status）、§3.4（软删过滤，reads 路径）、§3.6（配额）；错误见 §2.2 + §2.3；图像处理实现约束见 `api/agents/rules/image-pipeline.md`。

**打标队列本任务不实现。** 图片写入 `memes`（`tag_status = pending`）、进队列是这一步的终点；队列消费者（调视觉模型、生成 embedding）是另一个独立任务。因此本任务完成后库里的图 `tag_status` 都是 `pending`，`embedding` 为 null，搜索走 OCR/trgm 两路（向量路自动降级），行为正确。

1. **`POST /api/v1/imports`**
   - 读取 `{ files: [{ fileName, sizeBytes }] }`
   - 检查调用者的配额（已用 + 本批合计 ≤ 配额），超出返回 `QUOTA_EXCEEDED`（`details.remaining` 给出剩余字节）
   - 每个文件签发 R2 预签名 PUT URL（`temp/<batchId>/<fileName>` 键），返回 `{ batchId, uploads: [{ fileName, uploadUrl, tempKey }] }`
   - 批次元信息写库（状态 `pending`，记录 `uploaderID`、文件列表、创建时间）

2. **`POST /api/v1/imports/{batchId}/commit`**
   - 验证 batchId 属于当前用户
   - 接收 `{ items: [{ fileName, tempKey }] }`
   - 二次配额检查（签发到 commit 期间可能有并发上传）
   - 将文件列表压入处理队列，返回 202，**不同步等待**

3. **服务端处理管线**（队列消费，每个文件独立）
   - magic bytes 探测真实格式（不信扩展名，不信 `mime` 字段）
   - SHA-256 精确去重：命中 → `exact_dup`，删除 `temp/` 对象，发 SSE `item`
   - pHash 全库 Hamming 扫描：近似命中 → `needs_review`，**不打标**，发 SSE `item`，`temp/` 对象保留至用户处理
   - 两关都过 → 生成缩略图（`thumbs/` 前缀）→ 写入 `memes`（`tag_status = pending`）→ 进打标队列（消费者另实现）→ 发 SSE `item`（`result = "imported"`）
   - 每处理完一个文件发 `progress` 事件；全部处理完发 `done` 事件
   - 批次级失败发 `error` 事件后关闭连接
   - `is_animated` 必须用帧数判定——见 `api/agents/rules/image-pipeline.md §2`

4. **SSE 端点**
   - `GET /api/v1/imports/{batchId}/events`（`Accept: text/event-stream`）
   - 连接时先发一次当前 `progress` 快照（补齐断连期间的进度）
   - 连接断开不影响队列消费

5. **批次快照** `GET /api/v1/imports/{batchId}`
   - 返回批次当前状态（`total`, `done`, `skipped`, `pending`, `needsReview`, `failed`）
   - 元信息保留 24 小时，但 `needs_review` 条目在用户处理前不清理

6. **待确认队列**
   - `GET /api/v1/imports/reviews`：当前用户全部 `needs_review` 条目（跨批次），每条含 `{ fileName, tempUrl, sizeBytes, width, height, distance, existing: { id, url, uploaderName, sizeBytes, width, height, createdAt } }`
   - `POST /api/v1/imports/reviews/{batchId}/{fileName}`：`action = "import"` 则走正常入库流程（复用管线后段），`action = "skip"` 则删除暂存对象并标记跳过

7. **回填本文档**：完成后在「api 端验收」小节回填实测情况，说明三类路径（精确重复、近似重复、正常入库）各自测了什么、SSE 重连是否验过。

### web 端

**涉及的 SPEC：** §6.2（presign 接口、commit、SSE 格式）、§1.4（SSE 事件类型与字段）、§5.2.6（Meme 对外表示，待确认页展示已有图用）；错误见 §2.2 + §2.3。

**依赖：** api 端的 `POST /imports`、`commit`、`GET /imports/{batchId}/events`、`GET /imports/reviews`、`POST /imports/reviews/{batchId}/{fileName}` 需先上线，web 才能联调。骨架可先行，进度模拟用 mock。

1. **`src/lib/api.ts` 新增**
   - `presignImport(files: { fileName: string; sizeBytes: number }[])`
   - `commitImport(batchId: string, items: { fileName: string; tempKey: string }[])`
   - `fetchBatchStatus(batchId: string)`
   - `fetchReviews()`
   - `resolveReview(batchId: string, fileName: string, action: 'import' | 'skip')`
   - SSE 用原生 `EventSource`，不包成 api 函数——`EventSource` 不走 `fetch`，放进 `lib/api.ts` 会破坏「只有这一个文件发请求」的约束。在页面组件或 feature hook 里直接用 `new EventSource('/api/v1/imports/{batchId}/events')`，关闭时 cleanup。

2. **`src/routes/import.tsx`**（新建）
   - 文件选择区：支持点击和拖拽，显示待上传文件列表（文件名 + 大小）
   - 上传流程：presign → 对每个文件 `fetch(uploadUrl, { method: 'PUT', body: file })` 直传 R2 → commit → 建立 SSE 连接显示进度
   - 进度区：每个文件一行，显示 `imported` / `exact_dup` / `needs_review` / `failed` 四种状态
   - 完成摘要：`done` 事件后展示 `{ total, imported, exactDup, needsReview, failed }` 数字，`needsReview > 0` 时展示「查看待确认」入口
   - 错误处理：`QUOTA_EXCEEDED` 展示剩余配额、`UNSUPPORTED_FORMAT` 和 `FILE_TOO_LARGE` 逐文件展示（不中断整批）、`INTERNAL` 展示 `requestId`
   - SSE 断线时自动用 `GET /imports/{batchId}` 拉快照补齐进度，再重连

3. **待确认视图**（可以是 `/import?tab=review` 或独立入口，执行者自行判断是否值得独立路由）
   - 双图并排：左侧待确认图（`tempUrl`）、右侧已有图（`existing.url`），各显示尺寸、大小、上传者、时间
   - 显示相似度（`distance` 越小越像，展示方式自定）
   - 「仍然导入」和「跳过」两个操作，操作后移出列表
   - 当前用户没有待确认条目时展示空状态
   - **禁止弹中途确认框**（见 SPEC §6.2.3）

4. **`src/App.tsx`**：注册 `/import` 路由（套 `RequireAuth`），导航加「导入」入口

5. **`src/styles.css`**：追加布局样式，只写结构性 CSS，不写装饰性样式（见 `web/AGENTS.md §5`）

6. **回填本文档**：完成后在「web 端验收」小节回填实测情况，说明实测了哪个浏览器、上传路径（含 `needs_review` 触发路径）和待确认操作是否验过。

### 总管裁定

- **`existing` 可为 `null` 是契约缺口，不是实现走偏。** SPEC §6.2.3 原文把 `existing` 写成必有对象，而 api 的读路径按 [§3.4](../../spec/03-auth-permission.md) 过滤 `deleted_at is null`，关联图被软删时必然取不到——是文档漏了软删这条必经约束，不是代码擅自放宽。已补进 [SPEC §6.2.3](../../spec/06-endpoints.md)：`existing` 与 `tempUrl` 均可空，此时**不删条目、不自动入库**，客户端展示「原图已不存在」/「预览已过期」，两个操作照常可用（依据 [§9.7](../../spec/09-decisions.md)，重复的理由消失了也不替用户做决定）。web 端已按此实现，无需返工。
- **`bigint` 序列化成字符串这件事写进 SPEC。** 手写接口类型在 `sizeBytes` 这一处错过两次（搜索任务写成 `number`，本次导入的 `api-imports.ts` 同样是手写才发现），说明它不是某个执行者的疏忽而是缺文档。已补进 [SPEC §7.1](../../spec/07-naming.md)，并明确 `web` 的响应类型必须从 `api` 派生。这也是本次唯一需要沉淀的跨端结论——导入管线本身的契约在 §6.2 早已写定，实现未偏离，**不新增 §9 条目**。
- **`web/scripts/verify-import.mjs` 与替身不进提交**，与搜索任务同一裁定：一次性断言脚本，依赖替身和联调时点状态，不是可长期跑的回归套件。`api/scripts/__tmp-env.ts`、`api/scripts/__tmp-phash.ts` 同样是临时探测脚本，提交前清掉（`api/scripts/eval.ts`、`gen-fixtures.ts` 是正式脚本，保留）。要长期回归能力，等有种子数据后另起正式测试任务，不靠这些脚本续命。
- **打标队列消费者确认不在本任务范围。** 关闭后库里的图 `tag_status` 全是 `pending`、`embedding` 为 null，搜索走 OCR/trgm 两路并自动降级——这是预期行为，不是缺陷。队列消费者另起任务。
