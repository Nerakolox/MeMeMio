# 骨架搭建

**状态：`done`（已归档 2026-09-14）** · 创建 2026-09-13 · 更新 2026-09-14


## 为什么

现在项目只有文档，一行代码都没有。

骨架的价值不在"先跑起来"，在于**把几个只能在工程层面定下来的东西定下来**：两个工作区怎么共享类型、`shared/vocab/` 两端怎么读、本地开发怎么起、构建产物怎么进一个镜像。这几件事定错了，后面每个功能都要绕着它写。

**它不依赖前三项任务。** 骨架不碰具体词条、不碰供应商行为、不碰打标质量。

## 两端各自做什么

| 端 | 做什么 |
|---|---|
| api | 工程配置、migration、错误中间件、env 校验、Dockerfile、compose |
| web | Vite 配置与代理、路由骨架、`api.ts` 单一出口 |

放在跨端任务里，是因为**类型链路和 vocab 读取这两件事只有两端一起做才验证得了**。一端单独"做完了"证明不了任何事。

## 先落地的验证点

这几条不是功能，是**用来证明约束确实生效**的：

1. **改 `api` 的一个字段名，`web` 必须编译失败。**证明类型链路真的通了，而不是两边各写一份长得像的类型
2. **删掉 `CONFIG_ENC_KEY`，进程必须退出**，不能带着空 key 起来
3. **migration 没跑就启动，必须报错**而不是自动跑——生产环境自动跑 migration 是事故来源
4. **一条软删记录，默认查询必须查不到**

第 1 和第 4 条建议直接写成测试留在仓库里。

### 实测结果

**1. 改字段名 → web 编译失败：过。** 把 `api/src/routes/health.ts` 里 `vocabVersion` 改成 `vocabVersionRENAMED`，`cd web && npm run typecheck` 报两处：

```
src/lib/api-contract.ts(22,3): error TS2353: 'vocabVersion' does not exist in type
  '{ status: "ok"; startedAt: string; vocabVersionRENAMED: string; }'
src/routes/home.tsx(22,79): error TS2339: Property 'vocabVersion' does not exist ...
```

已改回。`web/src/lib/api-contract.ts` 是留在仓库里的编译期断言。

> ⚠️ **这条保证的闸门是 `npm run typecheck`，不是 `npm run build`。** `web` 的 build 只跑 `vite build`（esbuild，不做类型检查）。这是为了让 Dockerfile 的 web 阶段不必把 `api/` 源码和 `api/node_modules` 一起 COPY 进去。代价是：**typecheck 必须进提交前检查和 CI**，漏了这条，类型链路就只是个摆设。结论已落进 `docs/deployment.md §5`。

**2. 缺 `CONFIG_ENC_KEY` → 退出：过。**

```
环境变量校验未通过，拒绝启动：
  ✗ CONFIG_ENC_KEY 未设置

字段清单见 docs/environments.md §1，样例见 .env.example。
```

退出码 1，报的是变量名，不回显任何值。

**3. 迁移没跑就启动必须报错：过。** 库建好但没迁移时启动 api：

```
数据库迁移落后：已应用 0 / 1 条。
未应用：0000_create_core_tables

迁移不会在启动时自动执行（docs/deployment.md §6）。请手动跑：
  本机   cd api && npm run migrate
  部署机 docker compose run --rm app node dist/migrate.js
```

退出码 1，点名待跑的迁移，**没有自动跑**。逻辑在 `src/data/migration-state.ts`：比对 `migrations/meta/_journal.json` 与 `drizzle.__drizzle_migrations` 的条数。

**4. 软删记录默认查不到：过。** `api/tests/soft-delete.test.ts` 跑在真库上。同文件另外两组也过了：

- **权限不对称**——非上传者 `edit` 成功、`delete`/`retag` 被拒且 `code` 是 `FORBIDDEN`，`'User'`（管理员）可以。这组用例存在的意义就是挡住「顺手补一个归属检查」的改动。
- **`phash` 没有唯一约束**——`phash` 相同、`content_hash` 不同的两张图都能建记录；`content_hash` 相同则被数据库直接拒绝。库里实测：`memes_content_hash_key` 唯一，`memes_phash_idx` 是普通 btree。

### 测试

`npm test`：23 个用例，4 个文件全绿。

| project | 文件 | 用例 | 连库 |
|---|---|---|---|
| unit | `lib/env.test.ts` · `lib/redact.test.ts` · `routes/health.test.ts` | 16 | 否 |
| integration | `tests/soft-delete.test.ts` | 7 | **是**，`mememio_test` |

拆成两个 vitest project，边界是「要不要数据库」——为了让「Docker 没起」和「代码写错了」红得不一样。集成那组的 global-setup 会自己建 `<库名>_test` 并跑迁移，不碰开发库。

> ⚠️ **global-setup 只能 import 零依赖的 `tests/helpers/db-url.ts`。** 它里面先 `loadEnvFile` 再用变量看着没问题，但 import 在函数体之前就执行完了——只要间接 import 到 `src/env.ts`，env 校验就会在 `.env` 加载之前跑然后 `exit(1)`，整个测试一个用例都没跑就死。已经踩过一次。

### 顺带修掉的三个构建缺陷

Dockerfile 在此之前**从来没有被真正构建过**，`docs/deployment.md` §5 里那份跑不出来：

1. api 阶段 `npm ci --omit=dev` 之后 `npm run build` → `sh: 1: tsc: not found`。`tsc` 是 devDependency。改成 `npm ci` + `npm run build && npm prune --omit=dev`。
2. `COPY a b   # 说明` 这种行尾注释在 Dockerfile 里不是注释，`#` 被当成源路径，报 `"/#": not found`。所有说明挪到单独一行。
3. prune 掉 devDeps 后镜像里没有 `pino-pretty`，而 `logger.ts` 原本只按 `NODE_ENV` 决定挂不挂它——拿非 production 的 `NODE_ENV` 跑镜像会在加载日志器时就崩，**报错点离根因很远**。改成探测「装没装」而不是「哪个环境」。

三条都已回写 `docs/deployment.md §5`。
