# 搜索页：`GET /search` 与 `/` 主入口

**状态：`done`** · 创建 2026-09-15 · 关闭 2026-09-15

## 为什么

`/` 当前是骨架自检页，只做链路连通性验证用，不是真正可用的功能。搜索是产品的核心入口——用户打开 Mememio 的第一件事就是用自然语言找图。

api 端目前没有 `GET /search` 路由，三路融合（pgvector 向量检索、pg_trgm 文本匹配、标签精确匹配）和 RRF 融合都还没实现，因此这是一个跨端任务。

搜索和浏览是两条完全独立的路径，见 [SPEC §6.3](../../spec/06-endpoints.md)：
- 搜索：三路融合，不分页，最多 100 条
- 浏览：条件筛选，游标分页，无限滚动

## 做完的标准

- [x] `GET /api/v1/search?q=...` 上线，返回 `{ items, degraded, rewritten }`
- [x] 每条结果含 `matchedBy` 字段（`["vector", "ocr", "tags"]` 的子集）
- [x] 向量通路不可用时（embedding 未配置、索引重建中），`degraded: true`，仅靠 OCR + 标签两路，不报错
- [x] `rewritten` 为 HyDE 改写后的查询，失败时为 `null`，不影响其余通路
- [x] 软删记录不出现在结果中
- [x] Web `/` 页面：搜索框 + 结果网格，替换现有骨架自检内容
- [x] `degraded: true` 时展示提示（不阻断搜索）
- [x] 空状态、加载中、错误状态三态完整

## 两端各自做什么

### api 端

**涉及的 SPEC：** §6.3.1（搜索接口参数与响应）、§5.2.4（embedding 字段）、§5.2.3（AI 产出字段，matchedBy 含义）、§5.2.5（软删过滤）、§3.4（软删过滤强制要求）；错误见 §2，响应约定见 §1.1。

实现细节（RRF 参数、HyDE 提示词、各通路权重）是 api 的实现约束，见 `api/agents/rules/retrieval.md`，本文档不重复定义。

1. **`GET /api/v1/search`**：
   - 参数：`q`（必填）、`limit`（默认 50，最大 100）。
   - 三路召回（能跑哪路跑哪路，降级不报错）：
     - **向量路**：对 `q` 做 embedding（或 HyDE 后做 embedding），pgvector 近邻查询。embedding 未配置或索引不可用时跳过，设 `degraded: true`。
     - **OCR/trgm 路**：`pg_trgm` 在 `search_text` 上子串匹配。
     - **标签路**：`q` 与词表词条精确匹配，命中则过滤该标签的图。
   - RRF 融合三路结果，取前 `limit` 条。
   - `matchedBy` 字段：每条结果标注被哪几路召回，只做展示，不参与排序。
   - `rewritten`：HyDE 改写后的查询文本，失败时为 `null`。
   - **所有结果必须过滤 `deleted_at is null`**（SPEC §3.4）。
   - 结果含 `favorited` 字段（当前登录用户是否收藏）。
   - 响应：`{ items: (Meme & { matchedBy: string[] })[], degraded: boolean, rewritten: string | null }`。

2. **数据层**：新增或扩展 `src/data/search.ts`，`searchMemes(q, limit, actorId)` 函数。软删过滤在数据层统一处理。

3. **回填本文档**：完成后在「api 端验收」小节回填实测情况，说明三路各自测了什么、降级行为是否经过验证。

### web 端

**涉及的 SPEC：** §6.3.1（接口参数与响应字段）、§5.2.6（Meme 对外表示）、§5.4（收藏乐观更新）；错误展示见 §2。

**依赖：** api 端需先完成 `GET /search`，web 端才能做完整联调。骨架可先行。

1. **`src/lib/api.ts` 新增**：
   - `SearchResult` 类型（`Meme & { matchedBy: string[] }`）
   - `SearchResponse` 类型（`{ items: SearchResult[], degraded: boolean, rewritten: string | null }`）
   - `fetchSearch(q: string, limit?: number)` 函数

2. **`src/routes/home.tsx` 替换** 骨架自检内容，实现真正的搜索页：
   - 搜索词放 URL query string（`?q=...`），不放组件 state（见 `agents/rules/state-navigation.md` §1）。这样搜索结果可以分享。
   - 输入框：输入完成后（回车或失焦）触发搜索，不做实时搜索。
   - `degraded: true` 时在结果区顶部展示提示，说明向量通路不可用、结果可能不全，不阻断展示。
   - `rewritten` 非 null 时可在结果区展示「搜索理解为：…」，帮助用户理解结果来源，可选展示。
   - `matchedBy` 可作为每张图的轻量角标（如「向量+OCR」），不用于排序。
   - 收藏按钮：乐观更新，失败回滚（与浏览页一致）。
   - 空状态（无结果）、加载中（骨架）、错误状态三态完整，错误展示 `requestId`。
   - 搜索结果不分页——服务端返回什么就展示什么，不加「加载更多」。

3. **`src/styles.css`**：追加搜索页布局样式，只写结构性 CSS，不写装饰性样式（见 `web/AGENTS.md §5`）。

4. **回填本文档**：完成后在「web 端验收」小节回填实测情况，说明在哪个浏览器实测过搜索、降级提示、收藏三条路径。

### 降级行为：验证过，两个方向都测了

**降级成立（向量路跑不了，接口不报错）：**

- **embedding 未配置** → `degraded: true`，`rewritten: null`，OCR + 标签照常出结果，且没有任何一条结果的 `matchedBy` 声称含 `vector`。用 `search.test.ts` 的全套用例打（该文件的六个 embedding 环境变量刻意留空）。
- **embedding 服务返回 5xx** → `search-vector.test.ts` 起一个本地 HTTP 假服务（固定端口 `38921`，冒充 OpenAI 兼容接口），让 `ai/provider.ts` / `ai/embedder.ts` / `ai/hyde.ts` 三层走**真实代码路径**，只把对端换成假服务，然后让 `/v1/embeddings` 返回 500。断言 `degraded: true` 且 OCR 结果仍在。
- **HyDE 改写失败**（`/v1/chat/completions` 返回 500）→ `rewritten: null`，但**不算降级**（`degraded: false`），向量路改用**原始查询**做 embedding，断言假服务收到的 `input` 是原查询。
- 未配置时**根本不调** HyDE：`search.test.ts` 全程没有改写请求，也没有 `rewritten` 非 null 的情况。HyDE 只服务向量路，不跑向量路时调它是白发一次外部请求。

**降级不误报（向量路正常时不假装降级）：**

- 配好 embedding 后 → `degraded: false`，`matchedBy` 含 `vector`，近邻最近的排最前。
- `rewritten` 确实被用上了：断言转发给 embedding 的 `input` **含改写文本、不含原始查询**；查询侧的 instruct 前缀按 `Instruct: <任务>\nQuery: <文本>` 拼，文档侧不加。
- 假服务返回 **2048 维**向量（长于 `EMBED_DIM = 1024`），所以 embedder 的「客户端截断 + 重新归一化」这条分支是被真实走过的，不是绕过去的。

### 软删过滤

数据层 `src/data/search.ts` 的**四条**查询各自显式带 `isNull(memes.deletedAt)`（`search_text` 路、文件名路、标签路、按 id 取回详情），三路各有一条集成测试专门验软删行不出现——规则里点名过「三路是最容易只修一路的地方」。HTTP 层另有一条端到端验。

### 过程中改掉的一个真 bug

`src/lib/rrf.ts` 对**同一路内重复出现的 id 重复计分**（`expected 0.0325 to be 0.0164`）。是测试先红、代码后修的。修法是每一路内用 `seenInPath` 集合去重，名次按去重后的序号算。这条依赖数据层「每路返回的 id 不重复」的隐含假设，一旦上游改了（比如 join 出重复行），融合分就会静默翻倍。

### 2. 降级提示路径

**`degraded: true` 是拿真 api 的响应验的，不是编的。** 当前 dev 库为空且 embedding 未配置，直接 curl 真 api：

```
GET /api/v1/search?q=猫  →  200  {"items":[],"degraded":true,"rewritten":null}
```

用这个真实响应形状驱动页面，实测：顶部出现降级提示、**结果区照常渲染不被拦截**、提示文案说明向量通路不可用结果可能不全。另测 `degraded: false` 时不出现提示（不误报）。
