# 复制每次都失败：取原图踩了自家 `<img>` 毒化的 HTTP 缓存

**状态**：`done`（2026-09-26 本端验收通过）
**性质**：**web 单端**。只动 `web/src/lib/clipboard.ts` 一个实现文件，加一个验收脚本，更正两条文档。
接口、字段、错误码、`spec/` 一行未动——这条根因是浏览器侧行为，没有跨端契约。

**为什么归档在这里**：结论（「取原图必须 `cache: 'reload'`」）已写进
[`web/agents/rules/clipboard-share.md` §4.1](../../web/agents/rules/clipboard-share.md)，那是它该在的家；
[SPEC §9](../../spec/09-decisions.md) 记的是**跨端**长期决策，这条不是，故未新增条目。

## 1. 报上来的现象

> 总是出现 复制失败：取不到原图（可能是 R2 的 CORS 没放行 GET），取不到原图（可能是 R2 的 CORS 没放行 GET），请点下面的链接手动保存　还不如我右键复制

三件事，件件是线索：**每次都失败**（不是偶发）、**同一句原因说了两遍**、**那句原因指名 R2 的 CORS**。

## 2. 根因：缓存里那份响应既没有 ACAO，又没有 `Vary`

四步，每一步都实测过：

1. 页面里有几处把**同一张原图**当 `<img>` 渲染——全屏阅览器 `toSlide`、编辑面板、动图 hover 播放。
   这些请求**不带 `Origin`**；
2. r2.dev **只在请求带 `Origin` 时才回** `Access-Control-Allow-Origin`，**并且只在那种时候才回
   `Vary: Origin`**（实测：带 Origin 两个头都有，不带两个都没有）；
3. 于是浏览器把一份**没有 ACAO、又没有 `Vary`** 的响应存进 HTTP 缓存。没有 `Vary` 意味着它匹配
   之后**任何**请求，**包括复制路径那次 cors 模式的 `fetch`**；
4. `fetch` 从缓存里拿到那份没有 ACAO 的响应 → CORS 检查失败 → `TypeError: Failed to fetch`
   → 界面报「取不到原图」。**而 bucket 的 CORS 是好的**，图也照显示（`<img>` 不过 CORS）
   ——所以这个失败看起来完全不像缓存问题，像部署配错了。

症状因此是「**图看得见、右键能复制，点『复制』每次都失败**」，且**只要这张原图被显示过一次就长期
如此**（缓存条目会被 304 续命）。用户那句「还不如我右键复制」正是这个形状：右键走的是另一条路，
不经过我们的 `fetch`。

### 实测证据（真 Chrome、干净 profile、真 R2）

| 做法 | 结果 |
|---|---|
| 同一地址先当 `<img>` 载入，再 `fetch(url)` | **抛 `TypeError: Failed to fetch`** |
| 同一地址 `fetch(url, { cache: 'reload' })` | ok 200，全量字节 |
| 从没载入过的地址 `fetch(url)` | ok 200 |
| `<img crossorigin="anonymous">` 之后 `fetch(url)` | ok 200 |

旁证：`reload` 那一次**会把缓存条目换成带 ACAO 的一份**（即「治好」）。这一点很重要——它让
「先量原因、再验产品代码」的两步必须**用两张不同的图**，否则第二步是假绿（见 §5）。

### 排除掉的

bucket 的 CORS（实测放行 GET，两个本地 origin 都拿到 `ACAO: *`）、`R2_PUBLIC_BASE_URL` 配错
（api 自 09-18 未变）、网络不通（直连与走代理都 200）、键前缀与编码（3633 个键逐个核对）、
对象不存在（那会返回 HTTP 状态码，而用户看到的是网络层拒绝）、CSP 与 service worker（都没有）、
mixed content。

## 3. 为什么本项目的验收一直抓不到它

`web/scripts/mock-api.mjs` 服务 `/media/` 时**同源**（同源请求不发 `Origin`，压根不进 CORS 这套
机制），而且挂了 `Cache-Control: no-store`（不入缓存，毒化无从发生）。**两条缺一不可**，
所以这个 bug 在对替身的验收里**根本无法出现**——不是断言写得不够多的问题。

## 4. 改了什么（`web/src/lib/clipboard.ts`）

1. **主修**：`fetchOriginal` 的 `fetch(url)` → `fetch(url, { cache: 'reload' })`。
   不用 `no-cache`：那是拿缓存里那份**本身就缺 ACAO** 的条目去问 304，合并后谁赢说不清。
   代价是每次取图真的下一次网络——错的字节没法用，这个代价必须付。
2. **文案不再猜原因**：「取不到原图（可能是 R2 的 CORS 没放行 GET）」→「取不到原图（请求被拦下或
   网络不通）」。猜错的原因比不说更坏：读的人拿着它去翻部署配置，而毛病在浏览器里。
   HTTP 状态码那种说得清的仍然照说（`原图返回 HTTP 404`）。
3. **同一句失败不再说两遍**：降级路径与下载失败**是同一件事**（两个 fallback 走同一个
   `fetchOriginal`），原来两条路都失败时会把原因打印两遍。现在失败分支只补结果：
   「复制失败：原图返回 HTTP 404，下载也没成，请点下面的链接手动保存」。

新脚本自带的跨域媒体源**照 r2.dev 实测的头形状摆**（带 `Origin` 才回 ACAO 与 `Vary: Origin`）——
那两行是它的全部意义所在，写成了注释警告：谁「顺手修正」成永远都发，它就从回归守卫变成假保险。
它另外守一条**假绿**：量原因用的是 `measured.png`，被测的 `poisoned.png` **全程只准 `<img>` 碰**

  界面那条路径由上面两套既有脚本覆盖。
