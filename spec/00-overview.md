## §0.1 范围

`api` 是业务 API 的唯一提供方，`web` 是唯一消费者。两者同域部署：`api` 挂载 `/api/*` 并托管 `web` 的静态构建产物，浏览器不跨域请求，会话使用 httpOnly cookie。

**库是共享的，不是每人一个。** 所有用户的上传进同一张 `memes` 表，检索时不按归属过滤。归属只用于写权限判断。这与常见的多租户 SaaS 相反，实现时不能照搬「每个查询都带 user_id」的直觉，理由见 [§9.1](09-decisions.md)。

本规范定义外部可见的字段、语义和行为。不定义：打标提示词内容、抽帧算法参数、RRF 的 k 值、HyDE 改写策略、pgvector 索引参数——这些是 `api` 的实现约束，见 `api/agents/rules/`。

## §0.2 主源与派生

| 事实 | 主源 | 派生物 |
|---|---|---|
| 字段语义、权限、错误、行为 | 本目录 | — |
| 请求 / 响应的 TypeScript 类型 | `api` 的 Hono 路由定义 | `web` 经 RPC 消费，无生成步骤 |
| 标签词表本体 | `shared/vocab/vocab.json` | 打标提示词、输出校验、前端筛选 UI |
| 数据库结构 | 迁移文件 | — |

**类型只保证形状，本规范保证含义。** 下列内容不在类型系统里，必须有测试或联合验收依据：

- 写操作的归属检查（类型不知道谁能删）
- 读路径的软删过滤（类型不知道 `deleted_at` 该被过滤）
- 双通道降级顺序与触发条件
- 标签值是否落在词表内
- 导入幂等性与去重语义

不能因为「类型检查通过」就声称契约符合。

## §0.3 状态

| 状态 | 含义 | 可否实现 |
|---|---|---|
| proposed | 尚在讨论或依赖外部探测结果 | 只做调查，不做依赖该语义的实现 |
| accepted | 设计已对齐，等待实现或验证 | 可以 |
| stable | 已通过验证并进入基线 | 可以按现行约定消费 |
| deprecated | 已有替代方案，处于退出窗口 | 按迁移计划处理 |

未注明状态的章节为 `accepted`——它们来自已对齐的设计文档，但**本项目当前没有任何 `stable` 条目**，因为还没有实现和验证。

明确标记 `proposed` 的：桌面端拖拽发送路径（[§9.2](09-decisions.md)）、各供应商的 `dimensions` 与 `json_object` 实际支持情况（[§9.7](09-decisions.md)）、词表 v0.1 的具体词条（[§4.2](04-vocabulary.md)）。这些依赖 [供应商探测任务](../joint-tasks/2026-09-13-provider-spikes.md) 和 [评测集任务](../joint-tasks/2026-09-13-eval-set.md) 的结果。

## §0.4 基线与兼容

当前 SPEC 0.1.0-draft，对应产品 0.1.0（未发布）。章节号是引用标识，不等于软件版本号。

接口以 `/api/v1` 为大版本。兼容新增字段不改 URL，破坏性修改须另立迁移任务。

消费者必须忽略未知响应字段；请求未知字段返回 `VALIDATION_FAILED`。新增响应字段不等于允许客户端写入该字段。

**词表变更不是兼容变更。** 删除或重命名一个标签会让已有记录的该标签失去意义，必须按 [§4.4](04-vocabulary.md) 处理存量数据，不能只改 JSON 就发布。
