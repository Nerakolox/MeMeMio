# shared/vocab

固定标签词表的**主源**。`api` 和 `web` 都从这里读，不维护第二份。

规则、变更流程、校验要求见 [SPEC §4](../../spec/04-vocabulary.md)。本文只讲怎么用这个文件。

## 当前状态

**v0.2.0 · `proposed`**

词条是一份可用的起草版本，**尚未经评测集验证**。可以基于它写消费词表的代码，但**不要对具体词条做硬编码分支**——`if (tag === '摆烂')` 这种写法会在词表转 `accepted` 时变成需要人工排查的债。

v0.2.0 把语义维度从两个（情绪 / 场景）拆成五个，理由与迁移见 [语义维度拆分](../../joint-tasks/2026-09-22-语义维度拆分.md)，规则见 [SPEC §4.3](../../spec/04-vocabulary.md)。

转 `accepted` 的条件：[评测集](../../joint-tasks/2026-09-13-eval-set.md)验证不同模型的输出确实能对齐到这份词表，且[词表任务](../../joint-tasks/2026-09-13-vocab-v1.md)完成一轮人工筛选。

## 结构

```jsonc
{
  "version": "0.2.0",
  "status": "proposed",
  "expressions": [ ... ],       // 面部表情：脸上是什么样（视觉事实）
  "emotions":    [ ... ],       // 情绪：图里的人 / 动物在感受什么
  "tones":       [ ... ],       // 表达语气：这张图怎么说话
  "purposes":    [ ... ],       // 聊天用途：发它想完成什么交流动作
  "scenes":      [ ... ],       // 生活情境：和什么现实场合有关
  "tags": {
    "subject": [ ... ],         // 主体：图里是什么
    "style":   [ ... ]          // 风格：长什么样
  },
  "aliases": { "服了": "无语" }  // 归一化映射
}
```

> ⚠️ **五个语义维度互相不能推导**，这是拆开它们的全部理由。「微笑」是 `expressions` 的词条，把它写进 `emotions` 是越界，服务端按维度校验、直接丢掉（不搬到正确的那一维）。判据表见 [SPEC §4.3.1](../../spec/04-vocabulary.md)。

> ⚠️ **`tags` 在 JSON 里分组，在数据库里是扁平的。**
>
> `subject` / `style` 的分组**只是词表文件里的归类**，方便人读和维护。存进 `memes.tags[]` 时是一个扁平数组，校验时也扁平匹配；前端也把两组拼成一段渲染（`web/src/lib/vocab.ts` 的 `tagOptions`）。不要在数据库或接口里保留这个分组结构。

## aliases 怎么用

模型输出「服了」时，服务端归一化成「无语」再写库，**不算校验失败**。

`aliases` 的键**绝不能同时出现在任何一个维度的词条列表里**——那会造成「归一化成自己」的死循环，也说明词表设计有重复。这一条和「一个词只能属于一个维度」都由 `api/src/vocab.test.ts` 守住，不用自己肉眼查。

alias 只做单跳，不做链式解析。`A → B` 且 `B → C` 是配置错误。

## 消费方

| 消费方 | 用来做什么 |
|---|---|
| `api` 打标提示词 | 把六个维度的清单拼进 prompt，模型只能从里面挑 |
| `api` 输出校验 | 写 `memes` 前**按维度**校验，不合法走 `AI_INVALID_OUTPUT` |
| `api` 人工编辑校验 | 同一套，[不开后门](../../spec/04-vocabulary.md) |
| `api` 词表自检 | `src/vocab.test.ts`：维度互斥、alias 单跳、alias 不撞词条 |
| `web` 筛选 UI | 渲染六个维度的筛选分区（`VocabSections`） |
| `web` 标签编辑控件 | 用户只能选，不能自由输入 |

提示词里把词表放在**消息最前面**——DeepSeek 一类的服务端前缀缓存会自动命中，这部分几乎免费。

## 改它之前

1. 读 [SPEC §4.4](../../spec/04-vocabulary.md) 的变更流程表，确认你这次改动属于哪一类
2. 删除和重命名**必须附带数据迁移**，只改 JSON 会让存量记录变成非法值
3. bump `version`
4. **跑评测集**——词表是打标质量的地基，影响不能靠看几张图判断

改词表默认按不兼容变更处理，要开 [joint-task](../../joint-tasks/README.md)：`api` 的校验和 `web` 的筛选 UI 同时消费它。
