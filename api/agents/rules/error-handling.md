# 错误、日志与密钥

错误结构与错误码见 [SPEC §2](../../../spec/02-errors.md)。本文是实现约束。

## 1. 统一出口

所有错误经过一个中间件转成 [SPEC §2.1](../../../spec/02-errors.md) 的信封。**handler 里不手写错误响应体**——手写的那几个迟早会漏字段。

未捕获的异常一律转成 `INTERNAL` + `requestId`，**原始 message 只进日志，不进响应**。数据库错误、第三方 SDK 的报错里可能带连接串、带 key。

`requestId` 每个请求生成一次，同时出现在响应和该请求的所有日志里。排障以它为准。

## 2. `message` 面向用户

中文，可直接展示。`details` 结构随 `code` 而定。

**客户端按 `code` 分支，不解析 `message` 文本**——所以改 `message` 措辞是自由的，改 `code` 不是。改 `code` 的含义要走 [SPEC §8.3](../../../spec/08-collaboration.md)。

## 3. 失败不等于错误

本项目大量使用降级。判断标准：**用户需不需要为此做点什么？**

| 情况 | 返回错误？ |
|---|---|
| 打标失败，图片入库为 `needs_manual` | ❌ 正常返回，`tagStatus` 说明状态 |
| embedding 未配置，搜索只走两路 | ❌ 正常返回，`degraded: true` |
| 测试连接没通过 | ❌ **200**，结果在响应体里 |
| 用户填的模型不支持图片输入 | ✅ `AI_UNSUPPORTED`，他得去改配置 |
| 超配额 | ✅ `QUOTA_EXCEEDED` |

测试连接**不通过也返回 200**：它是一次诊断，不是一次失败的操作。

## 4. `rawResponse` 必须原样带回

测试连接失败时，把模型的原始返回**原样**放进响应。

**这是那个接口的核心价值。** 用户面对一个中转服务，只有看到原始返回才能判断是模型能力问题还是配置填错。**不要吞掉它，不要包装成友好文案，不要截断成前 100 字。**

> ⚠️ 但要确认原始返回里没有把请求头回显出来——个别中转服务会在错误体里带上收到的 Authorization。带 key 的部分必须脱敏后再返回。

## 5. 密钥

**三条，没有例外：**

1. 任何接口都不返回完整 API Key。配置接口返回 `"****" + 后四位`，且**客户端回传该字符串视为「不修改」**。
2. `CONFIG_ENC_KEY` 不出现在任何接口、任何日志、任何错误 `details` 里。
3. 解密后的 key 只在调用那一瞬间存在，不放进任何长生命周期对象。

脱敏函数放 `lib/`，是纯函数，有单测。**序列化层强制调用它**，不靠每个 handler 记得。

[总管入口](../../../AGENTS.md) 把这条列为三条硬边界之一。

## 6. 日志

结构化，第一个参数是对象：

```ts
log.info({ requestId, memeId, model, channel: 'fallback' }, 'vision degraded')
```

**每次降级必须记日志。** 静默降级和吞错误看起来一模一样，区别只在有没有留下记录。

记录内容的取舍：

| 记 | 不记 |
|---|---|
| `requestId`、`memeId`、`userId`、模型名、耗时 | API Key、会话 token、`CONFIG_ENC_KEY` |
| 错误类型、降级原因、重试次数 | 图片二进制、完整的用户上传内容 |
| 模型返回的**结构**（字段有没有、是不是空） | 模型返回的**全文**（可能含用户上传内容） |

最后一条有例外：排查拒绝形态时需要原文。那种情况下把样本脱敏后存进 [`docs/fixtures/responses/`](../../../docs/fixtures.md)，不是靠翻生产日志。

## 7. 批量导入里的错误

**整批不会因为一个文件失败而失败。**

单文件的失败作为 [SSE `item` 事件](../../../spec/01-http.md)的 `reason` 出现，不是 HTTP 错误。批次结束时 `done` 事件给出汇总。

例外：中途超配额，剩余文件全部标记失败并在 `done` 里说明原因——**不是静默停止**。
